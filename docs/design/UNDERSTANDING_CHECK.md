## (a) The film pipeline in my own words

A Bharat Blueprint episode is a web page that draws itself. Every frame is a pure function of one number, `t`. `index.html` loads scripts in a fixed order and exposes `window.seek(t)`; the renderer (`npx hyperframes render`) seeks `t` and screenshots the canvas at 1280x720, 30 fps. Nothing is filmed, and no pixels come from a model: the drawings are code.

The look lives in the shared engine (`src/blueprint.js`, byte-identical in Ep2 to Ep5): blueprint paper `#0b3763`, white ink, cyan for annotation, orange only for heat, mono type, a zoned drafting border, grid, grain and vignette. A persistent HUD frames every frame: scene label top-left (`SC.8 - WHAT IF`), title block bottom-right (`EP04 - 03:47`).

Two files carry the drama. `src/timing.js` lists the sentence clips: id, scene number, text, gap weight. A clip's duration is its measured audio length if known, otherwise words divided by 2.69. Gaps are then rescaled by a single factor so the film lands exactly on `TARGET` seconds however fast the voice actually reads. `src/film.js` lists the beats: each is anchored to the first word of a clip, arrives by fade or by a plotter sweep, inks in over a fraction of its hold, and may pin panel progress to specific words via `keys`. `src/epN.js` holds the actual drawings, one `PANELS['scene.beat']` per beat, each a function of progress `p`. Beat id `8.2` means scene 8, panel 2.

Audio is synthesised, not recorded. `build/make-audio.mjs` opens the same page in headless Chrome, reads `TIMING.clips` and `BEATS`, and lays the trimmed voice clips at their start times over a drone bed, with pen, sweep, tick, thump and chord cues tied to beat transitions and to hard-coded clip ids. It ducks effects under the voice and normalises to -16 LUFS. ffmpeg then muxes that mix with the silent render. Voice is ElevenLabs `eleven_v4`, one take per passage, cut into sentence clips on the longest silences.

So the automation is not about drawing better. It is about removing the copy-and-hand-edit step between episodes. Today each episode folder is a copy of the last, with the clip prefix, `TARGET`, scene names, `data-duration`, the `EP0n` HUD label and the sound-cue clip ids all retyped by hand. Those are the bugs this whole design set exists to prevent.

## (b) Generated vs authored

**Authored - a person or agent edits these; the only things that should ever be touched by hand.**

| Thing | Where it lives today | Becomes |
|---|---|---|
| The script (clip text) | `src/timing.js` CLIPS array | `script.json` |
| The beat list | `src/film.js` BEATS | `beats.json` |
| The scene labels and episode identity | `src/timing.js` SCENE_NAMES, `index.html`, `TARGET`, `clipPrefix` | `episode.json` |
| The drawings | `src/epN.js` PANELS | `panels.js` (about 80% of real effort) |
| The source ledger | `sources/SOURCE_REGISTER.md` (Ep1), `SOURCE_LEDGER.md` (Ep2) | `sources/LEDGER.md` - **missing entirely in Ep3, Ep4, Ep5** |
| The voice plan text | `narration/voice-plan.json` (Ep4, Ep5), `narration/passages.json` (Ep2, Ep3) | `narration/voice-plan.json` (two formats today) |
| Packaging choices | `upload/UPLOAD_*.md`, thumbnail PNGs | `packaging/packaging.json` |

**Generated - nobody edits; regenerated byte-for-byte.**

`index.html`, `timing.js`, `film.js` (thin wrappers over kit core), `narration/measured.js`, `audio/trim/*.wav`, `audio/mix.wav`, `renders/*.mp4`, `qc/*` reports, `packaging/*` outputs.

**Read-only forever:** `S*/FINAL/**`, `narration/raw/**` once a take exists, `audio/daniel/**`.

**The kit** (`_shared/kit/engine`, `core`, `sfx`, `fonts`, `schemas`, `templates`, `cli`) is code I write once against tickets and Claude reviews. It is not per-episode data.

## (c) Questions and contradictions found

Q1 to Q16. Full detail with options and my recommendation for each is in `QUESTIONS.md`; this is the summary.

### Contradictions inside the spec set

**C1 (Q1) - Spec 02 says the page loads `episode.json` / `script.json` / `beats.json` as `window.EPISODE`. A `file://` page cannot do that.**
I tested it in the actual Chrome build this project uses. `<script src="data.json">` raises `SyntaxError: Unexpected token ':'` because JSON is not JS, and `fetch("data.json")` from a `file://` page fails with `Failed to fetch` because Chrome blocks file-origin fetch. The existing QC scripts (`build/test-engine.mjs`) load `index.html` through `pathToFileURL`, i.e. `file://`. HyperFrames' own renderer serves over a local HTTP server (`serveStaticProjectHtml`), so fetch would work during render - but not in the QC path, which is where most gates live. My recommendation: generate a JS file (`episode-data.js`, `window.EPISODE = {...}`) so it works under both `file://` and HTTP.

**C2 (Q2) - Gate G9b ("duration within 0.1 s of `DURATION`") fails on Ep2's approved final as it stands today.**
Measured: Ep2's `data-duration` is `265` and its muxed MP4 is `265.000000`, but the computed `DURATION` from `timing.js` is `265.1667`. Three gaps (d35, d36, d37) hit the `MIN_GAP = 0.35` floor, so the rescale cannot shrink them further and the total lands slightly long. The difference is 0.167 s, above the 0.1 s tolerance. Ep3, Ep4 and Ep5 compute exactly (290.000, 293.000, 314.000). G3's 0.5 s tolerance would pass Ep2; G9b's 0.1 s would not. Recommendation: compare against `target`, not the recomputed `DURATION`, or widen G9b to 0.5 s.

**C3 (Q3) - Gate G10's thresholds contradict spec 05's own expectation.**
Spec 05 states that "Ep4's WHAT IF beat would be a WARN or FAIL", and I confirmed Ep4's beat 8.2 is visually sparse (empty `0.0` clock, empty FRIEND and NOT boxes - verified in a full-resolution frame). But I measured ink ratio at the end of every Ep4 beat using the spec's own formula (share of pixels brighter than paper by 40 levels, HUD strip excluded): **minimum 3.26 %, maximum 6.37 %, and beat 8.2 measures 4.37 %.** Every beat is far above the 2.0 % PASS threshold. The metric as written does not detect the defect it exists to detect, because Ep4's sparse beat still carries the large FICTIONAL SCENARIO stamp, the headline, the caption and the frame furniture - more ink than a genuinely sparse beat would have.

**C4 (Q4) - Gate G11's stated method does not implement what it says.**
Today's `text at p=1` test proves the text *function* draws the whole string at p=1. G11 wants to know whether a headline is *fully drawn on screen at 60 % of a beat*. I computed the actual panel progress at 60 % of each beat (PREROLL 0.2 s, `frac`, easing `1-(1-p)^1.5`): it is **at least 0.9197** for every Ep4 beat, while the highest `seg(p, a, b)` lower bound in `ep4.js` is **0.85** (168 calls, none above 0.9197). So all text is complete at 60 % of a beat - but only because these beats are long relative to their ink-in. That is luck, not a guarantee: a shorter beat or a later `seg()` bound would flip it.

**C5 (Q5) - Ticket T2 says the equivalence harness compares "a screenshot at every beat's mid-hold and end-of-hold (about 66 frames)".**
Ep4 has 32 beats, so 64 frames, not 66. Ep2 has 30 beats (60), Ep3 has 33 (66), Ep5 has 37 (74). The "66" matches Ep3, not Ep4. Cosmetic, but it is the number the ticket will be reviewed against.

**C6 (Q6) - T0's exclusion list, applied literally, still tracks about 322 MB and breaks T0's own "under about 50 MB" acceptance test.**
T0 says exclude `S*/FINAL/*.mp4`, `**/renders/*.mp4`, `**/audio/*.wav`, `**/narration/raw/*.mp3`, `**/audio/daniel/` and generated PNGs. Those patterns are right as far as they go, but gitignore's `*` does not cross `/`, so they miss `audio/fx/bed.wav` (24 to 29 MB in each of Ep2 to Ep5, about 107 MB in total), `audio/backup-before-levels/*.wav` (73 MB), `FINAL/voiceover-mp3/*.mp3` (30 MB), `audio/raw/*.mp3` and `audio/tone-test/*.mp3` (Ep2 only) and Ep1's `audio/raw_S*.mp3`. My recommendation: exclude `**/audio/**` and `**/FINAL/**` wholesale. With that, the tracked set is **226 text and code files, 1.77 MB** - comfortably under the bar.

**C7 (Q7) - Ep3's dead files are byte-identical to Ep2's live files, not merely similar.**
`E03/src/panels.js` and `E03/src/examples.js` have the same SHA-256 as `E02/src/panels.js` and `E02/src/examples.js` (`6439e4598d11` and `72c1ff749092`). `examples.js` defines `PANELS['1.3']`, which **collides** with `ep3.js`'s own `PANELS['1.3']`. Ep3's `index.html` loads neither, so it is inert today - but a stray script tag would silently replace Ep3's panel 1.3 with Ep2's bus-and-car drawing.

**C8 (Q8) - Spec 01's Chrome-path count is wrong: 37 script files, not "about 31".**
Measured: 39 files match the hard-coded path - 37 scripts, 1 `.bak` under `E02/audio/backup-before-levels/`, and 1 Markdown file (the brief itself, which quotes the path). The count matters because it is the number of places a fix must land.

**C9 (Q9) - Spec 01's line counts are correct, but the obvious PowerShell check disagrees.**
Spec 01 lists Ep4 `blueprint.js` 398 (actual 398), `objects.js` 187 (187), `ep4.js` 331 (331), `timing.js` 76 (76), `film.js` 101 (101). All correct. Note these are LF line counts; `Get-Content | Measure-Object -Line` reports 383, 178, 308, 73 and 96 because it does not count a trailing line. Harmless, but it will trip anyone who checks with the obvious one-liner.

### Gaps - places the spec is silent, where I must not guess

**C11 (Q11) - G6 requires a `stamp-fiction` clip that is the first clip of the WHAT_IF scene, but Ep2 and Ep3 do not put their stamp there.**
In Ep4 the stamp thump is at `f31`, which is the first clip of scene 8 (WHAT IF). In Ep5 it is at `g31`, the first clip of scene 9 (WHAT IF). Ep2's cue is at beat `9.1`, anchored to `d41`, which is scene 9's first clip. But Ep2 and Ep3 use **beat ids** for this cue while Ep4 and Ep5 use **clip ids**, and the manifest's `sound` block only has `stampRole` and `titleRole`. G6 as written can be applied mechanically to Ep4 and Ep5 but not to Ep2 and Ep3.

**C12 (Q12) - G5 ("every beat id has a `PANELS` entry and vice versa") fails on Ep2 today.**

So Ep2 has one orphan panel, and a faithful Ep2 migration would fail G5. Ep3, Ep4 and Ep5 are exact (33, 32 and 37 beats against 33, 32 and 37 panels).

**C13 (Q13) - Ep2's `narration/passages.json` has no `text` field at all, and Ep2's clips come from `narration_v6.txt`.**
Ep2's `passages.json` is an array of 18 `{id, clips}` objects with zero text. Ep3's is the same shape but with text on all 17. Ep4 and Ep5 use `voice-plan.json` with `passagesDetail[].text`. Ep2 also keeps five script versions (`narration_v2.txt` to `narration_v6.txt`, with v6 current) and 34 `c*` raw clips plus 33 `c*` trimmed clips alongside the current `d*` set.

**C14 (Q14) - The `role` list in spec 03 has no slot for Ep2's and Ep3's extra sound cues.**
Ep2's `make-audio.mjs` has two stamp thumps at `d34`, an hour-counter tick run at beat `10.3`, and a thump at beat `9.1`. Ep3's has two touchdown thumps tied to beats `2.3` and `4.2`, a sweep at beat `3.2`, and a thump at `9.1`. Only `stamp-fiction` and `title` appear in the manifest's `sound` block, and only six clip roles exist. The episode-specific cues have no home in the schema.

**C15 (Q15) - G10 and G11 assume a beat-indexed frame set while G9 measures the muxed file, and the two never meet.**
G8 and G9 measure the MP4; G10 and G11 measure frames from the page. `bb qc` is specified as "gates G8 to G11 on the muxed file and frames", so it needs both. Nothing states where the frames come from at `bb qc` time: regenerated, or read from `qc/frames/` produced earlier by `bb frames`.

**C16 (Q16) - `bb check` is described as read-only but writes `qc/check.md`.**
Spec 04 lists `bb check` as read-only in the Default column while the table says it writes `qc/check.md`. I read this as "does not modify source, only writes its report" and will follow the table unless told otherwise.

## (d) Which ticket I would start with, and why

**T0 - the safety net.**

Not because it is first, but because every later ticket's acceptance test depends on it:

- T1 says "nothing in `S01_*` changed"; T2 says "existing episodes are never edited in place"; T10 says "the user decides whether the original folder is replaced". All three need a **before-state** to compare against, and a git commit with pre-ticket hashes *is* that before-state. Without T0 there is no way to prove any later ticket respected the no-change rule.
- T2's equivalence harness needs a known-good baseline of Ep4's timings and frames. T0's `docs/INVENTORY.md` - the hash table plus the exact differing lines - is that baseline, and it is also what tells me which kit file version to pick in T1.
- The `node_modules` junction fragility (Ep2 to Ep5 all point at Ep1's `node_modules`) is a live hazard for every ticket that runs `node` inside an episode folder. Committing the tree first means the junctions can be replaced in T1 without risking the source.
- T0 is also the cheapest place to settle Q6 (the exclude-list gaps) and Q8 (the count), because it is the only ticket that touches `.gitignore`.
